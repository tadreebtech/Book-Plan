# API модерации объявлений

Операции доступны активным аутентифицированным пользователям с ролью `ADMIN`.
Идентификатор `id` берётся из ответа `GET /api/v1/admin/listings/`.

| Метод и адрес | Тело запроса | Новый статус |
| --- | --- | --- |
| `POST /api/v1/admin/listings/{id}/approve/` | Пустое | `APPROVED` |
| `POST /api/v1/admin/listings/{id}/reject/` | `{"rejection_reason": "Неверный адрес"}` | `REJECTED` |
| `POST /api/v1/admin/listings/{id}/hide/` | Пустое | `HIDDEN` |

Успешный ответ `200` содержит `id`, `moderation_status`, `rejection_reason`,
`moderated_at` (дата и время решения) и `moderated_by` (идентификатор администратора).
При отклонении пробелы по краям причины удаляются. При одобрении или скрытии
`rejection_reason` становится пустой строкой.

Каждый успешный запрос сохраняет решение и добавляет запись в `ResourceModerationLog`
в одной транзакции. Журнал хранит идентификатор объявления, администратора, предыдущий
и новый статусы, причину отклонения и время решения. Запись доступна по идентификатору
объявления и после его удаления.

| HTTP | Код | Когда возникает |
| --- | --- | --- |
| `400` | `VALIDATION_ERROR` | Причина отклонения отсутствует, пуста или передана не строкой |
| `403` | `UNAUTHORIZED` | Нет действующей аутентификации |
| `403` | `ACCESS_DENIED` | У пользователя нет доступа к модерации |
| `404` | `NOT_FOUND` | Идентификатор неверный или объявление не найдено |
