# API активации и деактивации ресурсов

Операции доступны активным аутентифицированным пользователям с ролью `ADMIN`.
Идентификатор `id` берётся из ответа `GET /api/v1/admin/listings/`.

| Метод и адрес | Тело запроса | Результат |
| --- | --- | --- |
| `POST /api/v1/admin/listings/{id}/activate/` | Пустое | `is_active = true` |
| `POST /api/v1/admin/listings/{id}/deactivate/` | Пустое | `is_active = false` |

Успешный ответ `200`:

```json
{"id": 12, "is_active": false, "upcoming_bookings": 3}
```

`upcoming_bookings` показывает, сколько подтверждённых броней этого ресурса ещё не
закончилось. По этому числу интерфейс может предупредить администратора перед
деактивацией.

Деактивация не отменяет брони: подтверждённые брони остаются `CONFIRMED`. Новые брони
на неактивный ресурс не создаются, их отклоняет проверка при бронировании.

Каждое изменение сохраняется вместе с записью в `ResourceActivationLog` в одной
транзакции. Журнал хранит идентификатор ресурса, администратора, действие
(`ACTIVATED` или `DEACTIVATED`) и время. Если ресурс уже в нужном состоянии, ответ тот
же `200`, но запись в журнал не добавляется.

| HTTP | Код | Когда возникает |
| --- | --- | --- |
| `400` | `VALIDATION_ERROR` | Идентификатор не является целым числом от 1 до 2^63 минус 1 |
| `403` | `UNAUTHORIZED` | Нет действующей аутентификации |
| `403` | `ACCESS_DENIED` | Пользователь не администратор или заблокирован |
| `404` | `NOT_FOUND` | Ресурс не найден |
| `405` | `METHOD_NOT_ALLOWED` | Запрос не методом `POST` |
